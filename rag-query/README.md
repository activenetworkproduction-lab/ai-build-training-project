## 四种查询方式对比

```bash
python rag-query/query_bm25.py "PostgreSQL 扩展"
python rag-query/query_vector.py "什么是向量检索？"
python rag-query/query_graph.py "RAG"
python rag-query/query_agentic.py "RAG 和向量数据库、图数据库分别是什么关系？"
```

| | BM25 | 向量 | 图 | Agentic |
|---|---|---|---|---|
| 原理 | 关键词匹配 + 词频统计 | embedding 语义相似度 | Cypher 遍历实体关系 | 大模型自己决定调用哪个/哪几个工具 |
| 需要模型 | 否 | 是（embedding） | 否 | 是（每一轮决策都要调用模型） |
| 擅长 | 问题包含明确专有名词 | 意思相近但没有相同关键词 | "A 和 B 是什么关系" | 复杂问题，一种方式不够时自动换/组合 |
| 查询次数 | 1 次 | 1 次 | 1 次 | 1~4 次（模型自己决定） |

## Agentic 查询：真实运行效果

问"RAG 和向量数据库、图数据库分别是什么关系？"，模型自己规划了 4 轮工具调用：

```
第 1 轮：vector_search("RAG 和向量数据库、图数据库的关系")   → 查到向量数据库和 RAG 的关系说明
第 2 轮：graph_search("RAG")                                → 查到 "RAG -[最常见的实现方式是]-> 向量数据库"
第 3 轮：bm25_search(...) + graph_search("图数据库")         → 补充图数据库相关的关键词/关系
第 4 轮：vector_search(...)                                  → 再确认一次知识图谱相关表述，然后给出综合回答
```

最终回答会分别说明"向量数据库和 RAG 的关系""图数据库和 RAG 的关系"，并且标注每部分
结论主要来自哪种查询方式——这就是"多轮迭代式 Agent"和"查一次就返回"的关键区别：
模型会根据已有结果自己判断"这个问题该不该换个方式再查一次"。

## Agentic 查询是怎么搭起来的

工具定义（`TOOLS`）用的是和 OpenAI function calling 完全一样的格式，Gemini 的
OpenAI 兼容接口也认这套格式。整个流程：

1. 把问题 + 工具定义发给模型
2. 模型要么返回"调用某个工具"（`tool_calls`），要么直接返回文字答案
3. 如果是工具调用：本地执行对应的 `search_bm25`/`search_vector`/`search_graph`，
   把结果当作一条 `role: tool` 的消息加回对话历史，再问模型一次
4. 重复最多 `MAX_ROUNDS`（4）轮，模型觉得信息够了就会直接给出文字答案

`dispatch_tool()` 和整个多轮循环已经完整实现，唯一留白的是 `call_model()`——
"把 messages 发给模型、拿到它的决策"这一步，课堂上现场实现。

## 为什么 BM25 按字符切分中文？

严谨的中文分词要用 jieba 这类库，但这里只是想演示 BM25 算法本身怎么工作，
按单字切分（每个汉字当一个词）足够看出"关键词匹配"和"语义相似"的效果差异，
不需要引入额外的分词依赖。
